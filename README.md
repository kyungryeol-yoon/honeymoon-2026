# Honeymoon 2026

Kyungryeol & Hojeong · 2026.09.14 – 10.04 신혼여행 일정 PWA.

- 배포: https://kyungryeol-yoon.github.io/honeymoon-2026/
- 홈 화면에 추가하면 오프라인에서도 일정이 열립니다.

## 구성

```
index.html          화면 전체 (CSS · JS 인라인)
data.json           여행 데이터 — 일정 수정은 여기만 고치면 됩니다
manifest.json       PWA 매니페스트
service-worker.js   오프라인 캐싱
icons/              앱 아이콘 (SVG 원본 + PNG)
```

## 시트를 다시 읽을 때

**증분** — 앱이 다듬어 온 이름·`place`·`move` 를 지키면서 시트 변경만 반영합니다.

```
python3 tools/sheet_sync.py <시트를_받아둔_json>   # 시트 → data.json (이전 것을 이어받음)
python3 tools/enrich.py                            # 새 항목에 종류·지도·칩 채우기
./tools/release.sh                                 # 검사 · 백업 · 버전
```

**초기화** — 이전 `data.json` 을 아예 안 읽고 시트에서 새로 만듭니다.

```
python3 tools/sheet_rebuild.py <시트를_받아둔_json>
python3 tools/enrich.py
./tools/release.sh
```

초기화하면 시트에 없는 것이 사라집니다 — `phrases` 한마디 · `place` 지도
검색어 · `move` 이동수단 · `chips` 하루 주의 · `star` 하이라이트 ·
`food.eat` 의 가격(→ "뭐 먹지" 칩이 통째로 꺼집니다).
`trip` · `cities` · 날짜↔도시 매핑은 앱 구조라 `sheet_rebuild.py` 안에 있습니다.

**그래서 초기화 뒤에는 그 층을 다시 얹습니다.**

```
python3 tools/relayer.py <예전_data.json>   # 예전 것에서 앱 전용 층만
python3 tools/enrich.py                      # 칩 플래그 다시 채우기
```

시트가 진실인 것(이름·설명·주의·옵션·숙소·예약상태)은 건드리지 않습니다.
`place`·`move` 는 **시각과 이름이 모두 같을 때만** 얹습니다 — 이름이 바뀐
항목에 옛 `place` 를 붙이면 엉뚱한 장소로 보냅니다 (9/19 옵션 순서가 달라
`Iseltwald` 자리에 `Rosenlaui` 가 오는 경우가 실제로 있었습니다).
못 얹은 항목은 실행하면 목록으로 찍어주니 사람이 확인하세요.

**매번 처음부터 다시 파싱합니다.** 이전 결과와의 차이를 쫓지 않습니다 —
시트 서식이 자주 바뀌어서(글머리 `-` 가 통째로 사라진 적도 있습니다)
차이만 보면 놓칩니다.

**무엇을 어디서 가져오는가**

| 시트에서 | 앱에서 (`CARRY`) |
|---|---|
| 시각 · 항목의 있고 없음 · 설명 · 주의사항 · 선택지 구조 | 이름 · `place` · `move` · `kind` · `booked` · 칩 플래그 · `tz` |

이름을 앱 쪽에서 쓰는 이유: 시트는 "이름 설명 설명" 을 한 줄로 적어 어디까지가
이름인지 알려주지 않습니다. 앱의 이름은 여러 차례 다듬은 것이라 매칭되면
그쪽을 씁니다. **새로 생긴 항목만 시트에서 이름을 뽑고, 실행하면 목록으로
찍어주니 사람이 확인해야 합니다.**

**이모지는 데이터에 넣지 않습니다.** 화면의 `kind` 이모지와 `star` 표식이
대신하고, 이름에 섞이면 지도 검색어와 복사에 딸려 들어갑니다.
`sheet_parse` 가 파싱 단계에서 걷어냅니다 (`→` `↔` 는 경로라 남깁니다).

**시트는 공백 여러 칸으로 항목을 나눕니다.** 한 칸 안에 줄바꿈 대신
`⚠️ 재입장 불가` + 공백 8칸 + `도마뱀 분수 (엘 드락)` 식으로 적혀 있습니다.
`\s+ → ' '` 로 뭉개면 이 경계를 잃어 **설명이 통째로 한 문장이 되고 이름에까지
딸려 들어갑니다.** `squash()` 가 2칸 이상을 `\x1f` 로 바꿔 살려 둡니다.

**`·`(U+00B7) 를 이모지 정규식에 넣지 마세요.** `[¡-¿]` 에 포함되는데
설명을 나누는 구분자라, 같이 지웠다가 설명 76개가 한 문장이 됐습니다.

**반복해서 걸린 것들** — 다음에도 확인하세요

- 시트 본문의 시각 참조(`마감 17:30~18:00`)가 새 항목으로 잡혀 **뒤 항목을

## 일정 수정하기

`data.json` 만 고치고 커밋하면 됩니다.

### 하루 추가

```json
{
  "date": "2026-09-14",
  "city": "bcn",
  "dayNo": 1,
  "chips": [
    { "t": "현금 €50", "warn": true },
    { "t": "여권 지참" }
  ],
  "items": [
    { "time": "10:30", "name": "인천 출발", "desc": "KE915", "map": false,
      "refs": [{ "label": "편명", "value": "KE915" }] },
    { "time": "17:40", "name": "사그라다 파밀리아", "end": "19:00",
      "place": "Sagrada Família",
      "prep": ["여권 필수", "±15분 입장", "탑 등반 X"] }
  ]
}
```

| 필드 | 설명 |
|---|---|
| `date` | `YYYY-MM-DD`. 오늘 날짜와 일치하면 "오늘"로 표시됩니다 |
| `city` | `cities[].id` 중 하나 (`bcn` `swi` `vce` `flr` `rom` `prg` `sel`) — 여정 라인의 노드 |
| `dayNo` | 여행 N일차 — 여정 라인의 진행도에 쓰입니다 |
| `label` | 헤더에 크게 뜨는 지명. 없으면 도시 이름. 스위스처럼 한 노드 안에서 거점이 바뀔 때 씁니다 (`라우터브룬넨` `그린델발트` `루가노`) |
| `map` | `place` 가 없는 일정의 지도 검색에 붙는 지역. 없으면 도시의 `map` |
| `stay` | **그날 밤 묵는 곳.** `{ name, place, addr }` — 칩 맨 앞에 고정, 탭하면 `addr`(없으면 `place`)가 복사됩니다 |
| | 체크인한 날에만 타임라인에 뜨고 다음 날 사라지던 문제 때문에 넣었습니다. 밤늦게 택시에서 보여줄 한 줄이라 **묵는 날마다** 적어주세요 (3박이면 3일 모두) |
| `cash` | 그날 현장에서 현금으로 낼 것. `{ amount, for, note }` — 칩에 강조 표시 |
| `chips` | 상단 알림. `warn: true` 면 도시 색으로 강조 |
| `items[].time` / `end` | `HH:MM`. `end` 가 없으면 다음 일정 시작까지로 봅니다 |
| `items[].name` | 탭하면 구글맵이 열립니다 |
| `items[].place` | 지도 검색어. **적으면 그대로 검색합니다** |
| `items[].map` | `false` 면 지도 링크를 만들지 않습니다 (이동·식사 등) |
| `items[].meet` | 투어 모임 장소. `{ time, where, place }` — 이름 바로 아래 강조, 탭하면 지도 |
| `items[].move` | 이 일정까지 가는 방법·시간 (`"도보 8분"`). 앞 일정 아래에 이어서 표시 |
| | `(추정)` 이 붙은 값은 시트에 없어 계산해 넣은 것이라 화면에서 흐리게 표시됩니다 |
| `items[].prep` | 그 일정에 필요한 준비물·주의사항. 일정 바로 아래에 태그로 붙습니다 |
| `items[].refs` | 편명·열차번호 등. 탭하면 클립보드로 복사됩니다 |
| `items[].kind` | 일정 종류. 이름 앞 이모지를 고릅니다 (아래) |
| `items[].booked` | 예약 상태 — `발권` `예약` `온라인` `상시`. 시각 옆에 ✅ 가 붙습니다 |

`chips` 는 그날 전체에 걸리는 주의사항, `prep` 은 그 일정 하나에만 해당하는 준비물입니다.
(예: 9/28 → `chips` 에 "현금 €46", 바티칸 투어 `prep` 에 "카드 불가 · 개인 입장권 사지 말 것 · 여권")

### 일정 종류 (`items[].kind`) · 예약 상태 (`items[].booked`)

훑어보다가 "이게 투어인지, 예약한 건지, 숙박인지" 를 바로 알기 위한 표식입니다.

**이모지를 `name` 에 직접 넣지 마세요.** `name` 은 지도 검색어이자 검색 대상이라
이모지가 섞이면 구글맵 검색어와 클립보드 복사에 다 딸려 들어갑니다.
`kind` 값만 적으면 `index.html` 의 `KIND` 표가 이모지를 붙입니다 —
이모지를 바꾸고 싶으면 그 표 한 곳만 고치면 됩니다.

| kind | | kind | | kind | |
|---|---|---|---|---|---|
| `wedding` | 💒 | `flight` | ✈️ | `train` | 🚆 |
| `bus` | 🚌 | `boat` | 🛥️ | `taxi` | 🚕 |
| `car` | 🚗 | `cable` | 🚡 | `tour` | 🎫 |
| `stay` | 🏨 | `meal` | 🍴 | `church` | ⛪ |
| `museum` | 🖼️ | `ruins` | 🏛️ | `nature` | ⛰️ |
| `walk` | 🚶 | `shop` | 🛒 | `photo` | 📷 |
| `rest` | 🛏️ | | | | |

**`kind` 를 일부러 비운 일정이 있습니다** — "도착 · 이동 · 복귀" 같은 연결 동작
(442개 중 57개). 모든 줄에 이모지가 붙으면 훑어볼 때 구분이 사라지기 때문입니다.
직전 교통편이 이미 아이콘을 달고 있어서 정보도 잃지 않습니다.

`booked` 는 구글 시트의 `✅발권완료` `✅예약완료` `✅온라인` `✅24시간` 을 옮긴 것입니다
(24건). 실제 예약번호는 저장소가 public 이라 넣지 않았습니다 — 상태만 표시합니다.

이모지는 기기 고유 색으로 그려지므로 도시 색이 먹지 않고 아이폰·안드로이드에서
모양이 다릅니다. 대신 폭을 `1.25em` 으로 고정해 이모지가 없는 줄과 이름 왼쪽이 맞습니다.
스크린리더에는 이모지 대신 `sr-only` 로 "항공." "예약 완료." 처럼 읽힙니다.

### 선택 가능한 일정 (`day.options`)

날씨·컨디션 보고 당일 고르는 날이 있습니다. `options` 가 **없는 날은 코드 경로가
기존과 완전히 동일합니다** — 이 필드를 안 쓰면 아무것도 달라지지 않습니다.

```json
{
  "date": "2026-09-20",
  "items": [ ...옵션과 무관한 공통 일정... ],
  "options": [
    { "id": "oeschinensee", "label": "Oeschinensee", "recommended": true,
      "summary": "곤돌라 + 호수 산책 · 왕복 2시간 40분 운전",
      "cash": { "amount": "CHF 56", "for": "곤돌라 왕복 2인" },
      "items": [ ...이 옵션을 고를 때의 일정... ] }
  ]
}
```

- `options[].items` 의 스키마는 기존 `items` 와 같습니다 (`time` `name` `desc` `move` `prep` `star` …)
- `recommended` 는 **하루에 최대 하나**. `release.sh` 가 검사합니다
- 옵션별 금액이 다르므로 `options[].cash` 를 넣으면 그날 현금 칩이 그걸로 바뀝니다

**동작**

1. 고르기 전 — 카드가 늘어서고, 타임라인·NOW 카드는 **공통 일정만** 씁니다.
   NOW 카드는 "선택 필요 · N가지 중 하나를 고르세요"
2. 고르기 전에도 **타임라인에 자리표시가 들어갑니다** — `08:30 – 18:00 · 3가지 중 선택`.
   9/20 처럼 공통이 4개뿐인 날은 이게 없으면 아침~저녁이 통째로 비어 보입니다.
   누르면 선택 카드로 데려갑니다
3. 고르면 — 공통 + 옵션 일정이 **시간순으로 합쳐집니다** (같은 시각이면 공통이 앞)
4. 선택은 `localStorage` 의 `hm26-option:<날짜>` 에 저장됩니다 (테마 저장과 같은 패턴)
5. 고른 뒤에는 칩 맨 앞에 선택이 뜨고, **탭하면 해제되어 다시 고를 수 있습니다**
6. 검색은 **아직 안 고른 옵션의 일정까지** 훑습니다
7. 인라인 백업에도 옵션이 들어가 **오프라인에서도 고를 수 있습니다**

선택이 바뀌면 `optRev` 가 올라가고, 이 값이 `tl` · `opts` · `up` 캐시 키에 섞여 있어
**호출자가 `resetSigs()` 를 부르지 않아도** 해당 영역이 다시 그려집니다.

현재 옵션이 있는 날: 9/17 · 9/18 · 9/19 · 9/20 · 9/21 · 9/23 · 9/25 (7일)

### 이동 수단 커버리지

장소가 바뀌는 구간에는 모두 수단이 적혀 있습니다 (`move` 75건 + 이동 자체가
일정인 것 39건). 이 중 **35건은 시트에 적힌 값, 40건은 추정값**입니다.
추정값에는 `(추정)` 이 붙고 화면에서 흐리게 나옵니다.

시트에서 확정하시면 `(추정)` 을 떼고 실제 값으로 바꿔주세요.
빡빡한 날은 추정을 믿지 마시고 현지에서 확인하시는 게 안전합니다.

`items` 는 시간순으로 적어주세요. `days` 는 순서가 섞여 있어도 날짜순으로 정렬됩니다.

### 지도 링크를 붙일지 말지

`map: false` 가 없으면 **모든 항목이 구글맵 링크**가 됩니다. `place` 가 없으면
이름이 그대로 검색어가 되므로, `"취침, Barcelona, Spain"` 같은 링크가 생깁니다.
눌러도 아무것도 안 나오는데 밑줄과 핀만 붙어 있어 눌러보게 됩니다.

원칙은 하나입니다 — **눌렀을 때 갈 데가 있어야 링크입니다.**

- 장소가 아닌 항목(기상 · 조식 · 취침 · 짐 정리 · 보안검사 …) → `map: false`
- 장소인데 이름이 오염된 항목 → `place` 에 깨끗한 검색어
  (`"몬세라트 대성당 €9/인 = €18"` → `place: "Santa Maria de Montserrat Abbey"`)
- 이름 자체가 지명이면 그대로 둬도 됩니다 (`Furka Pass` · `Bellinzona`)

현재 지도 링크 185개 중 **182개가 `place` 로 검색어를 지정**했고, 이름 검색은
3개뿐입니다. `release.sh` 가 "`place` 없이 동작 이름으로 링크가 걸린 항목" 을
찾아 배포를 막습니다.

**`place` 는 그 자체로 찾아지는 검색어여야 합니다.** 도시명을 자동으로 붙이지 않습니다 —
이동일에는 하루 안에 도시가 두 개라 (`로마 테르미니` 아침 / `카를교` 밤) 붙이면 오히려
엉뚱한 곳이 나오기 때문입니다. 그래서 여러 도시에 같은 이름이 있는 곳은
`"Pantheon, Roma"`, `"Palazzo Ducale, Venezia"` 처럼 직접 적어뒀습니다.

### 도시 색

`cities[].color` 는 다크 모드, `colorLight` 는 라이트 모드용입니다.
라이트에서는 배경이 밝아지므로 명도를 한 단계 낮춘 값을 씁니다.
여정 라인 아래 문구는 **직전 → 현재 → 다음**을 `나라 도시` 로 보여줍니다
(`이탈리아 베네치아 → 이탈리아 피렌체 → 이탈리아 로마`). 나라는 한 단계 흐리게 처리해
"나라 도시" 가 한 덩어리로 읽히고 도시가 도드라지게 했습니다.
`cities[].country` 가 이름과 같은 곳(스위스)은 나라만 한 번 씁니다.
양옆을 늘 `Seoul` 로 두면 매일 같은 문장이라 알려주는 게 없어서 바꿨습니다.
첫 도시 앞은 `Seoul`, `home: true` 인 마지막 도시(서울) 뒤는 `· 완주` 가 됩니다.

**`cities` 는 7개, 화면의 "6 Cities" 는 6개** — 서울(`home: true`)은 출발·귀국지라
완주 화면의 도시 수(`CITIES.filter(c => !c.home).length`)에서 빠집니다.
여정 라인에는 7개가 다 나옵니다. 도시를 추가할 때 이 차이를 기억하세요.

### 현지어 · 영어 한마디 (`phrases`)

`cities[].lang` 과 최상위 `phrases` 를 짝지어, 그날 도시의 언어로 자주 쓸 문장을
타임라인 아래에 보여줍니다. 탭하면 현지어 문장이 복사됩니다 (그대로 보여줘도 됩니다).

**`phrases.en` 은 도시와 무관하게 항상 아래에 함께 나옵니다.** 현지어가 안 통할 때
쓰는 공통 수단이라 언어팩과 별개로 취급합니다 (현지어 4줄 + 영어 10줄).

```json
"cities": [ { "id": "rom", "lang": "it", ... } ],
"phrases": {
  "it": {
    "name": "이탈리아어",
    "lines": [
      { "ko": "카드 결제 되나요?", "x": "Posso pagare con la carta?", "r": "뽀쏘 빠가레 꼰 라 까르따" }
    ]
  }
}
```

`ko` 한국어 · `x` 현지어(복사되는 값) · `r` 한글 발음. 셋 중 `r` 만 생략할 수 있습니다.
`lang` 이 없는 도시(서울)나 `phrases` 에 없는 언어는 이 영역이 통째로 숨습니다 —
그래서 `phrases` 를 빼도 기존 데이터가 그대로 동작합니다.

### 긴급 연락처 (`contacts`)

최상위 `contacts` 를 **`cities[].flag`(국가코드)로** 찾습니다. `flag` 가 이미 `ES` `CH` `IT` `CZ`
라서 도시에 새 필드를 넣지 않았습니다. `common` 은 나라와 무관하게 항상 아래에 붙습니다.

```json
"contacts": {
  "common": { "name": "어디서나", "lines": [
    { "label": "영사콜센터", "tel": "+82-2-3210-0404", "note": "24시간 · 유료" }
  ]},
  "CZ": { "name": "체코", "lines": [
    { "label": "긴급 (경찰·구급·소방)", "tel": "112" },
    { "label": "주체코 대사관 (프라하)", "tel": "+420-234-090-411", "note": "근무시간" }
  ]}
}
```

탭하면 `tel:` 로 바로 걸립니다. **`tel:` 은 데이터가 없어도 동작하므로**, 모든 게 무너진
상황에서 이 화면이 마지막까지 쓸모 있는 부분입니다. 그래서 인라인 백업에도 넣었습니다.

- `tel` 이 전화번호 형태(`^[+\d][\d\s()+-]*$`)가 아니면 그 줄은 렌더에서 버립니다
- 4자리 이하(`112` `144` `1414`)는 현지에서 바로 거는 번호라 강조 표시됩니다
- `flag` 에 해당하는 항목이 없는 나라(서울)는 영역이 통째로 숨습니다

> **번호는 반드시 공식 출처로 확인하고 넣으세요.** 현재 값은 2026-08-10 기준
> 외교부 공관 페이지(`overseas.mofa.go.kr`) 확인분입니다. 공관 번호는 바뀝니다 —
> 출발 전에 한 번 더 대조하시는 걸 권합니다.

### 스와이프 카드 칩 (`food` · `gift` · `say` + 빈 시간)

같은 알약 칩 하나를 눌러 그 자리에 카드를 펴고, 좌우로 넘겨 봅니다.
`CARDS` 표에 종류를 한 줄 더 적으면 새 칩이 생깁니다 — 카드 렌더·스와이프·
충돌 처리는 넷이 공유합니다.

| 칩 | 붙는 곳 | 내용 | 개수 |
|---|---|---|---|
| `🍽️ 뭐 먹지` | `items[].food` | `food.<city>.eat` 중 `price` 있는 것 | 40 |
| `🛍️ 뭐 사지` | `items[].gift` | `gift.<city>.buy` 전체 | 5 |
| `💬 이 말 하면 돼` | `items[].say` | `phrases[city.lang].lines` | 54 |
| `⏳ N분 비어요` | **자동** — 낮에 90분 이상 빌 때 | `food.spots` + `gift.spots` | 41 |

빈 시간 칩만 데이터가 아니라 **시간 계산으로 자동으로 꽂힙니다**(`gapHTML`).
낮 09:00~21:00 사이에서 `GAP_MIN`(90분) 이상 비면 그 자리에 한 줄이 생깁니다.
60분으로 낮추면 82곳이 되어 온종일 칩이 뜹니다 — 그래서 90분입니다.
새 데이터는 필요 없고 이미 있는 97곳(식당 76 + 가게 21)을 재활용합니다.

칩 합계 117개 / 타임라인 392줄 = **줄당 0.30개.** 이보다 촘촘해지면
칩이 배경이 되어 눈에 안 들어옵니다 (종류 이모지 때 57개를 비워둔 것과 같은 이유).

`say` 는 캠프 식사처럼 말 걸 일이 없는 자리에는 붙이지 않습니다.
현지어는 결제 문장 위주였는데 "이거 주세요 · 계산서 주세요 · 화장실 어디예요"
를 보태 4개 언어 각 7줄이 됐습니다.

### 식사 항목의 음식 카드 (`items[].food`)

19:30 에 폰을 열면 타임라인엔 "디너" 한 줄뿐입니다. 아래 "먹을 곳" 섹션까지
내려가면 위아래 시간이 안 보여서, **그 자리에** 펴기로 했습니다.

```json
{ "time": "13:00", "name": "점심", "kind": "meal", "food": true }
```

- `true` → 그날 `day.city` 의 음식. 문자열(`"food": "flr"`) → 그 도시 것
  (이동일에 다음 도시를 미리 보는 용도)
- 플래그가 없는 항목은 `foodToggle` · `foodCard` 가 빈 문자열을 돌려주므로
  **기존 렌더 경로와 완전히 동일합니다**
- `day.options` 안의 식사 항목에서도 동작합니다 (`withOption()` 머지 후 렌더)

**`🍽️ 뭐 먹지 · 8` 알약을 눌러 펴고 접습니다.** 항목 이름은 이미 구글맵 링크라
이름 전체를 토글로 쓰면 충돌합니다. 숫자는 그 도시 카드 메뉴 수입니다.

처음엔 아이콘만 든 22px 정사각 버튼이었는데 **실기기에서 안 보였습니다.** 두 겹이었습니다.

1. `🍽`(U+1F37D)은 변이 선택자가 없으면 **텍스트 표현(흑백)** 으로 그려집니다.
   `KIND` 표의 `🍴`(U+1F374)는 기본이 이모지라 잘 보여서 눈치채지 못했습니다.
   `U+FE0F` 를 붙여 컬러로 고정합니다.
2. `<button>` 은 UA 기본 색(검정)을 씁니다. `color` 를 안 주면 그 흑백 글리프가
   어두운 배경에서 사라집니다. **버튼에는 `color` 와 `background` 를 반드시 명시할 것.**

지금은 도시 색 테두리 + 글자를 함께 둬서 이모지가 안 그려져도 읽힙니다.

**카드 높이는 고정입니다**(`.fc-win { height:118px }`). 메뉴를 넘길 때 높이가
변하면 아래 일정이 밀려서 시간 비교라는 목적이 깨집니다. 넘치는 설명은
`-webkit-line-clamp` 로 자릅니다.

**카드에 오르는 건 `price` 가 적힌 메뉴뿐입니다.** 접힌 "먹을 곳" 칩 목록은
`eat` 전체를 그대로 쓰므로 정보를 잃지 않습니다 — 한 줄짜리 항목까지 카드로
넘기면 빈 카드를 여러 장 넘기게 됩니다. 도시별 카드 메뉴 수는
bcn 6 · swi 6 · vce 7 · flr 12 · rom 8 · prg 6.

`food.<city>.cardNote` 는 카드 하단 한 줄입니다. 도시마다 고정이라 메뉴를
넘겨도 높이가 변하지 않습니다 (이탈리아 3개 도시엔 banco/tavolo·Coperto 주의).

**스와이프 충돌** — 날짜 넘기기에 이미 좌우 스와이프를 쓰고 있습니다.
카드 위에서 시작한 제스처는 `tracking = false` 로 날짜 스와이프를 아예 끄고,
카드가 가져갑니다. 축은 처음 움직임으로 한 번만 정합니다 —
`|dx| > |dy| * 1.5 && |dx| > 30` 이면 가로(카드), `|dy| > 12` 면 세로(스크롤 양보).
가로로 판정된 뒤에만 `preventDefault()` 하므로 **카드 위 세로 스크롤은
그대로 동작합니다.** 양 끝에서는 이동량을 0.28 배로 줄여 "끝" 이라는 느낌만 남깁니다.

마우스·키보드에는 스와이프가 없으므로 하단 점(8개 이하)이 버튼입니다.
9개 이상이면 점 대신 `3 / 12` 로 바뀝니다.

카드를 넘길 때는 `render()` 를 부르지 않고 `transform` 만 직접 바꿉니다 —
DOM 을 새로 만들면 전환 애니메이션이 죽습니다. 대신 타임라인이 다시 만들어질
때(`tlSig` 에 `foodOpen` 포함) 보던 메뉴로 되돌려 놓습니다.

한 번에 하나만 열리고, 날짜를 바꾸면 닫힙니다. `localStorage` 에 저장하지
않습니다 — 일시적인 화면 상태입니다.

인라인 백업(최후의 오프라인 화면)에는 `food` 를 넣지 않았습니다. 서비스워커
캐시로 열리는 평소 오프라인에서는 정상 동작합니다.

### 먹을 곳 (`food`)

구글 시트의 도시별 표(꼭 먹어볼 음식 · 추천 식당 · 식당 팁)를 옮긴 것입니다.
최상위 `food` 를 **`cities[].id`** 로 찾아, 그날 도시의 것만 타임라인 아래에 보여줍니다.
목록이 길어(도시당 10~16곳) 기본은 접혀 있고, 헤더에 식당 수가 뜹니다.

```json
"food": {
  "bcn": {
    "name": "바르셀로나",
    "eat": [ { "n": "빠에야", "d": "해산물 or 발렌시아식 — 점심에", "star": true } ],
    "spots": [
      { "g": "타파스 (캐주얼)", "list": [
        { "n": "Cervecería Catalana", "a": "Passeig de Gràcia", "d": "줄 김 · 종류 가장 다양" }
      ]}
    ],
    "tips": [ "점심 13:30~15:30 · 디너 21:00~23:00 — 한국보다 늦습니다" ]
  }
}
```

- `eat` — 꼭 먹어볼 음식. `n` 이름 · `d` 한 줄 설명(생략 가능) · `star` 강조
- `spots[].g` — 그룹 이름 (타파스 / 빠에야 / 디너 …). 스위스는 마을 단위로 나눴습니다
- `spots[].list[]` — `n` 상호 · `a` 동네(오른쪽에 작게) · `d` 한 줄 설명 · `star` 강조
- `tips` — 식사 시간·팁·자릿세처럼 그 도시에서 미리 알아야 할 것

식당 한 줄을 탭하면 구글맵 검색으로 갑니다. 검색어는 **`이름, 지역`** 이고,
지역은 `list[].area` → `spots[].area` → `cities[].map` 순으로 씁니다.
`area` 는 **스위스 때문에 필요합니다** — 도시 하나(`swi`) 안에 라우터브룬넨·그린델발트·
루가노가 섞여 있어서 `Switzerland` 만 붙이면 엉뚱한 곳이 나옵니다.
체스키 크룸로프(프라하 소속)와 트라스테베레(로마)도 같은 이유로 `area` 를 적었습니다.

`food` 에 없는 도시(서울)는 이 영역이 통째로 숨습니다 — `food` 를 통째로 빼도
기존 데이터는 그대로 동작합니다.

### 기념품 (`gift`)

`food` 와 같은 틀입니다. 시트의 도시별 "기념품·쇼핑" 열을 옮겼습니다.
최상위 `gift` 를 `cities[].id` 로 찾아 그날 도시 것만 보여줍니다.

```json
"gift": {
  "prg": {
    "name": "프라하",
    "buy": [ { "g": "대표", "list": [
      { "n": "보헤미안 크리스털", "d": "Moser · Preciosa 정품 매장에서", "star": true }
    ]}],
    "spots": [
      { "n": "Albert · Tesco", "q": "Albert", "d": "식품 기념품 가성비" }
    ],
    "tips": [ "마지막 도시입니다 — 위즈에어를 지났으니 무거운 것은 여기서" ]
  }
}
```

- `buy[].g` — 그룹 (대표 / 식품·술 / 수공예 …), `list[]` 는 칩으로 깔립니다
- `spots` — 사는 곳. 그룹 없이 한 덩어리이고, 탭하면 지도로 갑니다
- `tips` — 면세 환급 기준, 가짜 구별법처럼 **사기 전에** 알아야 하는 것
- 헤더의 숫자는 `food` 는 식당 수, `gift` 는 물건 수입니다

**`q` — 지도 검색어만 따로.** 표시 이름에 한국어가 섞이면(`Casa Batlló 굿즈샵`,
`체스키 크룸로프 골목 가게`) 구글맵이 못 찾습니다. 그럴 때만 `q` 에 실제로 찍히는
이름(`Casa Batlló`, `Náměstí Svornosti`)을 적습니다. 화면에는 `n` 이, 지도에는
`q, 지역` 이 갑니다. `food` 에서도 똑같이 씁니다.

**무게 이야기를 팁에 넣어뒀습니다.** 9/30 `FCO → PRG` 위즈에어가 인당 20kg 이라,

### 예약번호

저장소가 public 이라 **예약번호·PNR·실명·이메일은 `data.json` 에 넣지 않았습니다.**
현재 `refs` 에 들어있는 건 편명·열차번호뿐입니다 (공개 시간표 정보).
실제 예약번호는 구글 시트에서 확인하세요.

꼭 넣어야 한다면 `mask` 를 쓰세요. 화면에는 뒤 4자리만, 복사는 원본이 됩니다.

```json
"refs": [
  { "label": "편명",     "value": "W46065" },
  { "label": "예약번호", "value": "1400828907951511", "mask": true },
  { "label": "좌석",     "note": "메일 확인" }
]
```

| | 화면 | 탭하면 |
|---|---|---|
| 그냥 `value` | `W46065` | 원본 복사 |
| `mask: true` | `••••••1511` | **원본** 복사 (토스트·aria 에도 값 노출 안 함) |
| `note` 만 | `메일 확인` | 아무 일 없음 (버튼 아님) |

가림표는 자릿수를 드러내지 않도록 항상 6개로 고정합니다.
`release.sh` 는 `mask` 없는 예약번호가 들어오면 배포를 막습니다.

  바로 옆에 시각이 이미 적혀 있습니다

  내일 첫 일정에도 안 붙입니다 (자기 전에 "13시간 뒤" 는 쓸모없음)

1초마다 도는 기존 D-day 타이머에 얹어 `tickLeft()` 로 갱신합니다 —
1분마다 도는 `render()` 만으로는 최대 59초 늦습니다.

**끄는 것도 분기마다 해야 합니다.** 처음엔 켜는 쪽(live)에서만 초기화해서,
여행 전 화면으로 돌아가도 배지가 그대로 남았습니다. 지금은 NOW 카드
분기 전체보다 앞에서 매번 끕니다.

시계 옆에 현재 **시간대**(KST · CEST …)를 표시합니다. 비행 중이나 시차가 바뀌는
시점에 "지금 어느 시간대 기준으로 날짜를 따지는지" 헷갈리지 않게 하기 위한 것입니다.
날짜 판정은 기기 시간대를 따르므로, 이 표시가 곧 판정 기준입니다.

타임라인의 각 시각 옆에 **한국 시간**이 함께 뜹니다 (`16:30  23:30 KST`).
날짜가 넘어가면 `⁺¹` 이 붙습니다.

**환산 기준은 폰이 어디 있느냐가 아니라 그 날의 도시입니다** — `cities[].tz`
(UTC 오프셋, 분). `data.json` 의 시각은 언제나 현지 시각이라 그래야 맞습니다.
예전엔 기기 시간대로 쟀는데, 출발 전 서울에서 보면 차이가 0이라 환산이
통째로 사라졌습니다. "9/23 저녁 6시 45분" 은 보이는데 "한국은 새벽 1시 45분"
은 안 보였습니다. 로밍이 안 잡혀 폰 시계가 안 바뀐 순간에도 같았습니다.
서울 일정은 `540 - 540 = 0` 이라 저절로 숨습니다.

**하루 안에 시계가 바뀌는 날(9/14)** 은 항목마다 `tz` 와 `tzl`(표시용 이름)을
적습니다. **항목의 `tz` 가 도시보다 우선**합니다. 작은 시간대 알약(`tzl`)은
항목에 적은 날에만 붙습니다 — 도시 단위로 붙이면 338개 전부에 붙습니다.

```
01:20 – 05:20  [KST]    01:20–11:20 KST     ← 인천 출발 · 도하 도착
05:20          [GMT+3]  11:20 KST
14:40          [CEST]   21:40 KST
```

비행편처럼 출발지·도착지 시계가 다르면 `endTz` 로 도착 쪽을 따로 적습니다.
`01:20 – 05:20` 만 보면 새벽 5시 도착으로 읽히지만 실제로는 11:20 KST 입니다.

**`tz` 가 있는 날은 "지금/다음" 판정도 실제 시각(epoch)으로 계산합니다.**
예전엔 기기 로컬 시각으로만 비교해서, 비행 중 KST→CEST 로 바뀌는 순간
NOW 카드가 7시간 점프했습니다. 이제 그러지 않습니다.

오늘 카드가 화면 밖으로 나가거나 다른 날을 보고 있으면 우하단에 **[오늘]** 버튼이 뜹니다.

### 1분마다 도는 갱신

앱은 1분마다 `render()` 를 돌려 시계와 "지금" 표시를 맞춥니다. 예전에는 그때마다
타임라인·이후목록(줄마다 랜드마크 SVG)·한마디·연락처를 **통째로 다시 만들었습니다.**
DOM 을 버리고 새로 만들면 **사용자가 길게 눌러 선택해둔 텍스트가 사라집니다.**

지금은 블록마다 의존값을 서명(`changed(key, sig)`)으로 남겨 바뀐 것만 다시 그립니다.

| 블록 | 다시 그리는 조건 |
|---|---|
| 타임라인 | 날 · 진행중 항목 · 접힘 · 시간대 · 테마 |
| 이후 목록 | 날 · 남은 일수 · 테마 |
| 여정 라인 | 현재 위치 |
| 한마디 | 도시 언어 |
| 긴급 연락처 | 나라 |
| 랜드마크 | 아이콘 |

재렌더 3.5ms → 1.1ms, 선택한 텍스트가 유지됩니다.
**인라인 색(`--c`)이 박힌 블록이 있어 테마를 바꾸면 `resetSigs()` 로 전부 무효화합니다.**

### 서비스워커가 로밍·오프라인에서 지키는 것

이 앱의 유일한 치명적 실패는 **현지에서 오프라인일 때 일정이 안 뜨는 것**이라,
서비스워커는 아래 세 가지를 보장합니다.

1. **모든 네트워크 요청에 4초 타임아웃 + `AbortController`**
   타이머만으로 끊으면 원래 `fetch` 는 살아 있어서, 응답 없는 요청이 백그라운드에서
   계속 데이터를 먹습니다. 로밍 중에는 이게 그대로 요금·배터리입니다.
   그래서 `timedFetch` 가 `signal` 로 연결 자체를 끊습니다.
2. **백그라운드 갱신에도 같은 타임아웃**
   캐시를 먼저 띄우고 뒤에서 갱신하는 경로(`cacheFirst` · `handleNavigation`)도
   `timedFetch` 를 씁니다. 예전에는 무제한 대기라, 오프라인에 들어가는 순간
   셸 파일마다 매달린 `fetch` 가 쌓였습니다.
3. **캐시 쓰기를 `event.waitUntil` 로 보호**
   `respondWith` 만으로는 응답을 돌려준 뒤의 `cache.put` 이 보장되지 않습니다.
   서비스워커가 유휴 종료되면 그대로 잘립니다. 특히 `networkFirst` 의 `data.json`
   캐싱이 잘리면 **다음번 오프라인에 일정이 통째로 안 뜹니다.**
   그래서 `fetch` 핸들러가 응답 약속과 백그라운드 갱신을 모두 `waitUntil` 에 겁니다.

캐시 쓰기가 실패해도(용량 등) 받아온 응답은 그대로 화면에 넘깁니다 —
캐시 문제로 지금 보고 있는 일정까지 잃지 않게.

일정 데이터는 **3단계**로 찾습니다. 앞이 실패하면 다음으로 넘어갑니다.

1. 네트워크 `./data.json` — **5초 타임아웃**
2. `localStorage` 에 저장해 둔 직전 데이터
3. `index.html` 안에 심어둔 인라인 백업 (`#fallback-data`)

2·3단계로 떴을 때는 화면 위에 출처를 알리고 [다시 시도] 버튼을 띄웁니다.
셋 다 실패하면 원인이 적힌 에러 화면이 뜹니다. 온라인으로 돌아오면 자동으로 다시 받습니다.

> 타임아웃이 없으면 응답이 끝내 안 올 때 `await` 이 풀리지 않아
> 화면이 "불러오는 중"에서 영영 멈춥니다. 실제로 그 문제가 있었습니다.
> `AbortController` 만으로는 부족해서 `Promise.race` 로 끊습니다.

지도 링크는 `google.com/maps` 로 나가므로 **오프라인에서는 열리지 않습니다.**
좌표를 넣어 `geo:` 로 여는 방법도 있지만 좌표를 다 모아야 해서, 지금은 안내만 합니다.

- 오프라인이 되면 칩 아래에 한 줄 안내가 뜹니다 (지도가 안 열린다는 것 + 대신 뭘 할 수 있는지)
- 그 상태에서 장소 이름을 탭하면 빈 탭을 여는 대신 **검색어를 클립보드로 복사**합니다.
  택시 기사에게 보여주거나, 신호가 잡히는 곳에서 그대로 붙여넣으면 됩니다

출발 전에 **구글맵에서 각 도시 오프라인 지역을 미리 받아두세요.** 그러면 앱 밖에서는
지도가 오프라인으로도 동작합니다. (앱이 대신 해줄 수 있는 일이 아닙니다)

이미 일정이 떠 있는 상태에서 새로고침이 실패하면 **화면을 지우지 않습니다.**
여행 중에 정보를 빼앗기는 게 최악이라 알림만 띄우고 이전 데이터를 그대로 둡니다.

**일정을 고쳐 배포한 뒤에는 `service-worker.js` 의 `VERSION` 을 올려주세요.**
그래야 캐시가 통째로 교체되고 열려 있는 화면이 자동으로 새로고침됩니다.
`./tools/release.sh` 가 이걸 자동으로 해줍니다 (아래 참고).

## 로컬에서 보기

```sh
python3 -m http.server 8765
# http://127.0.0.1:8765
```

`file://` 로 열면 service worker 와 `fetch` 가 막히므로 반드시 서버로 띄워야 합니다.

## 아이콘 다시 만들기

`icons/icon.svg` · `icons/icon-maskable.svg` 를 고친 뒤:

```sh
./tools/render-icons.sh
```

Chrome 헤드리스로 렌더링합니다. ImageMagick 내장 SVG 렌더러는 stroke 와 `H`/`V`
path 명령을 빠뜨려서 아이콘이 깨집니다.

## 배포

**커밋 전에 이것만 돌리면 됩니다.**

```sh
./tools/release.sh
```

1. `data.json` 문법·구조 검사 (날짜 중복, 시간순, 도시 id)
2. 예약번호·이메일이 그대로 들어갔는지 검사 — 걸리면 **중단**합니다
3. 인라인 백업 데이터 갱신 (`tools/build-fallback.py`)
4. `service-worker.js` 의 `VERSION` 자동 증가

그 다음 `main` 에 푸시하면 GitHub Pages(Deploy from a branch · `main` / root)가 반영합니다.

`VERSION` 을 안 올리면 **폰에 옛날 화면이 그대로 뜹니다.** 스크립트를 쓰는 이유가 이것입니다.

## 폰에서 갱신이 안 될 때

홈 화면에 추가한 앱은 서비스워커 캐시를 씁니다. `VERSION` 이 올라갔으면
한 번 열었다 닫으면 교체되는데, 그래도 옛날 화면이면 앱을 완전히 종료 후 다시 여세요.

### 지난 일정 접기 · 남은 일정

밤에 열면 하루의 절반 이상이 이미 끝난 일정입니다 (9/26 21:45 기준 18개 중 17개).
그래서 **오늘을 보고 있을 때만** 지난 일정을 한 줄로 접고, 탭하면 펼칩니다.
날짜가 바뀌면 다시 접힙니다. 펼치고 접을 때 보고 있던 "지금" 일정이 화면에서
튀지 않도록 스크롤을 보정합니다.

NOW 카드 시각 옆에 `· 남은 일정 7개 · 마지막 22:30` 이 붙습니다.
저녁에 페이스를 가늠하는 용도라 진행 중인 일정이 있을 때만 나옵니다.

### 밤에 보는 화면

오늘 일정이 다 끝나면 NOW 카드 아래가 **내일 첫 일정**으로 바뀝니다.
07시 이전이면 도시 색으로 강조합니다 — 9/17 은 02:30 기상, 9/27 은 06:45
투어 미팅이라 자기 전에 반드시 보여야 합니다.

첫 일정 시작 전에는 태그가 `지금` 이 아니라 `곧 시작` 입니다.

## 움직임

전부 CSS 애니메이션이고 **`prefers-reduced-motion` 이면 전역 규칙 하나로 모두 꺼집니다.**

| 언제 | 무엇 |
|---|---|
| 앱을 열 때 | 헤더(랜드마크 → 도시명 → 부제 → 여정선)가 한 번 차례로 올라옴 |
| 날짜를 넘길 때 | 랜드마크·도시명이 **넘긴 방향으로** 들어오고, 일정이 차례로 올라옴 |
| 지난 일정 펼칠 때 | 같은 방식으로 차례로 올라옴 |
| 항상 | 여정 라인의 현재 도시 노드가 천천히 숨쉼 (`j-halo`, 3.2초) |
| 하이라이트 | 날이 바뀔 때만 ✦ 마크가 살짝 피어남 |

**1분마다 도는 자동 갱신에서는 재생되지 않습니다.** `renderedDate` 로 날이 실제로
바뀐 렌더인지 판별해서 그때만 `.enter` / `.in-fwd` / `.in-back` 를 붙입니다.
이게 없으면 가만히 둔 화면에서 1분마다 일정이 다시 올라와 성가십니다.

### 하이라이트 (`items[].star`)

그날의 명장면에 `"star": true` 를 붙이면 ✦ 마크와 함께 조금 크고 굵게 나옵니다.
현재 31개(하루 1~2개)입니다. 너무 많으면 의미가 없어지니 하루 2개를 넘기지 마세요.

### 만나러 가는 곳

출발 전에만 나오는 도시 6칸(3열 2행). 탭하면 그 도시 첫날로 이동합니다.
출발까지 35일 동안은 이 화면이 앱의 거의 전부라 카운트다운만 두기엔 허전해서 넣었습니다.
